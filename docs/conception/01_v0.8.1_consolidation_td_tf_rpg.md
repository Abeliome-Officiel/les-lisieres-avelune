# v0.8.1 — Consolidation TD / TF / RPG

Périmètre : décisions issues du travail spécialisé sur les trois axes après la
v0.8.

Cette version ne constitue pas un nouveau prototype. Elle corrige et précise le
socle mécanique utilisé comme référence pour le prototype suivant.

---

# 1. Architecture générale

## Corcite unique

Le joueur pilote un même Corcite à travers trois lectures complémentaires :

- TD : interaction avec les vagues et la Lisière ;
- TF : fonctionnement organique, production et réseaux ;
- RPG : identité, évolution, connaissance et relations au monde.

Ces axes ne sont pas trois jeux indépendants.

Ils doivent alimenter le même état persistant du Corcite.

## Abandon de la règle « un ordre par axe »

**Acté**

La règle historique :

- un ordre TD ;
- un ordre TF ;
- un ordre RPG ;

par tour était une simplification de prototype.

Elle n'est plus une règle générale du jeu.

La progression est limitée naturellement par :

- les durées ;
- les ressources ;
- les capacités ;
- les travailleurs ou équivalents ;
- les dépendances ;
- les files de production ;
- l'état du Corcite ;
- les conditions propres à chaque mécanisme.

Le RPG n'est notamment plus considéré comme une file d'ordres symétrique du TD
et du TF.

---

# 2. TD — Tower Defense

## Deux niveaux de lecture

**Acté**

Le TD comporte deux mécanismes liés :

1. le Corcite agit comme une défense globale vis-à-vis de la vague ;
2. à l'intérieur du Corcite, la vague suit un parcours entrée → sortie sur
   lequel les structures internes peuvent agir.

## Vague initiale

Pour le premier socle testable :

- la composition initiale de la vague n'est pas recomposée en cours de passage ;
- sa puissance peut être réduite ;
- ses effets négatifs peuvent être réduits ou transformés ;
- certains effets positifs peuvent être transportés vers la Lisière ;
- des éléments bénéfiques peuvent également être transmis.

## Résolution automatique et manuelle

**Acté**

Deux modes doivent rester possibles :

- résolution automatique fondée sur l'état préparé ;
- résolution manuelle avec interventions limitées.

Le mode manuel ne permet pas de créer de nouvelles tours pendant la résolution.

L'automatique doit être viable mais ne doit pas toujours être optimal.

## Tours

Un socle fonctionnel commun est disponible pour tous les Corcites.

Les variations peuvent ensuite provenir :

- de la race ;
- de la classe ;
- du métier ;
- du TF ;
- du RPG ;
- de découvertes ou déblocages.

La conception doit éviter qu'une identité donnée rende une fonction fondamentale
du TD inaccessible.

## Captation

**Acté**

Deux valeurs doivent être distinguées :

1. ce que le Corcite obtient réellement ;
2. ce que cette captation retire effectivement à la vague.

Cette séparation évite qu'un Corcite placé tôt dans la trajectoire puisse
accaparer mécaniquement l'intégralité de la ressource disponible au détriment
des suivants.

Des plafonds ou quantités émises peuvent participer à l'équilibrage.

## Anneaux

Les anneaux ne définissent pas à eux seuls une difficulté fixe.

La position relative reste pertinente, notamment par l'exposition et les effets
issus des premières rencontres avec la vague.

Les passages secondaires et effets complexes restent des extensions futures.

## Volume de contenu

Ordre de grandeur provisoire :

- environ 75 tours uniques si les combinaisons ne constituent pas un système
  majeur ;
- une quantité plus faible peut suffire si les combinaisons produisent une
  diversité mécanique réelle.

Ce nombre est une cible de conception, pas un engagement de lancement.

## Télémétrie

Le système doit pouvoir journaliser au minimum :

- caractéristiques des vagues ;
- puissance reçue ;
- puissance retirée ;
- résultats par anneau et par Corcite ;
- effets négatifs ;
- captation ;
- performances des tours ;
- résolution automatique ou manuelle ;
- cicatrices ;
- récupération.

L'objectif est de permettre le rééquilibrage à partir du comportement réel du
jeu.

# 3. TF — Tycoon / Factory

## Fonction

Le TF représente le fonctionnement organique et productif du Corcite.

Il couvre notamment :

- population ;
- santé ;
- énergie ;
- besoins ;
- entretien ;
- stockage ;
- transport ;
- espace ;
- mémoire ;
- production ;
- fabrication.

Les besoins issus du TD ou du RPG peuvent être matérialisés dans le TF lorsqu'il
est pertinent qu'ils utilisent des ressources ou infrastructures.

## Production

Les catégories générales retenues sont :

- ressources brutes ;
- ressources transformées ;
- composants et produits ;
- unités ou bâtiments ;
- tours.

Une unité de production n'effectue qu'une production à la fois.

Une file d'attente peut exister.

Le changement de production intervient après la production en cours, sous
réserve de disposer des ressources nécessaires.

## Stockage

**Acté**

Il n'existe pas une capacité globale abstraite par catégorie.

Chaque bâtiment ou unité de stockage possède sa propre capacité.

Un stockage plein peut bloquer le flux correspondant.

## Connexions

Lorsqu'une unité produit directement pour une autre, un tampon adapté peut être
créé automatiquement afin de permettre l'accumulation nécessaire au traitement
aval.

En cas de bifurcation, le joueur doit pouvoir définir :

- une priorité ;
- ou une répartition.

## Transport interne

Le prototype n'a pas besoin de simuler tous les déplacements entre stockage et
unités.

Les connexions directes unité → unité restent en revanche significatives.

## Énergie

**Acté**

Modèle hybride :

- capacité énergétique normale ;
- réserve permettant un dépassement ponctuel ;
- conséquences progressives si le dépassement perdure ;
- conséquences accrues lorsque la réserve est épuisée.

Les valeurs exactes relèvent de l'équilibrage.

## Entretien

**Acté**

L'entretien est un coût général du Corcite.

Le socle actuel ne simule pas une usure détaillée individuelle de chaque unité.

Les conséquences précises d'un déficit d'entretien restent à équilibrer.

## Automatique et manuel

L'automatique doit être viable mais non optimal.

Le manuel peut offrir un potentiel supérieur en échange :

- de davantage de décisions ;
- de davantage de risque ;
- d'une gestion plus fine.

## Arrêt d'une production

Un arrêt en cours de traitement peut entraîner des pertes proportionnelles à
l'avancement.

## Commerce

Le commerce n'est pas une condition de survie du Corcite dans le premier socle.

Les échanges peuvent fournir des avantages et ne doivent pas rendre le solo
structurellement invalide.

Les systèmes commerciaux complexes sont hors du périmètre immédiat.

---

# 4. RPG

## Nature du RPG

**Acté**

Le RPG n'est pas un troisième moteur d'ordres comparable au TD ou au TF.

Il constitue une couche textuelle, narrative et évolutive du Corcite.

Il organise notamment :

- identité ;
- choix de développement ;
- compétences ;
- capacités ;
- connaissances ;
- recherches ;
- relations ;
- mémoire ;
- accès ;
- déblocages ;
- modificateurs.

Il peut modifier numériquement le jeu mais sa fonction première reste
l'incarnation et l'évolution.

## Interventions du joueur

Le joueur intervient principalement lorsqu'un élément réclame réellement une
décision :

- seuil atteint ;
- choix de progression ;
- découverte ;
- déblocage ;
- lancement ou renouvellement d'une recherche ;
- interaction narrative ;
- changement d'orientation.

Il n'est pas nécessaire de produire artificiellement une action RPG à chaque
tour.

---

# 5. Conséquence pour le prototype suivant

Tout prototype logiciel dérivé de la v0.8 doit être relu à partir de cette
version.

En particulier, une implémentation imposant encore systématiquement un ordre TD,
un ordre TF et un ordre RPG par Corcite et par tour est considérée comme
obsolète.
