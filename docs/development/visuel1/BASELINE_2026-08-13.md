## Temps de préparation du plan de rendu

100 itérations par taille de scène :

| Formes | p50 | p95 |
|---:|---:|---:|
| 1 | 0,0208 ms | 0,1863 ms |
| 16 | 0,1459 ms | 0,6181 ms |
| 64 | 0,2661 ms | 0,7641 ms |
| 128 | 0,3820 ms | 1,0110 ms |

Ces mesures concernent uniquement la transformation d'un payload public synthétique en plan de rendu neutre JavaScript. Elles ne mesurent pas :

- le dessin Canvas/WebGL/WebGPU ;
- le GPU ;
- la fréquence d'image ;
- les shaders ;
- la génération de textures ;
- les particules réelles ;
- la mémoire graphique ;
- le réseau ;
- l'énergie ;
- le coût cumulé avec le jeu et le sonore.

## Mémoire

Les variations de heap observées pendant ce micro-benchmark sont trop sensibles au GC pour constituer une baseline fiable. Elles restent journalisées dans les logs CI mais ne sont pas retenues comme métrique de décision à ce stade.

## Lecture

La préparation du plan de rendu n'est pas actuellement un goulot d'étranglement démontré. Cela autorise le prochain probe graphique, mais ne préjuge en rien du coût du renderer réel.

## Gate suivante

Le renderer probe devra mesurer séparément :

1. temps CPU navigateur ;
2. temps de frame et stabilité p95/p99 ;
3. mémoire JS et mémoire graphique lorsque observable ;
4. nombre de formes visibles ;
5. coût de la transformation majeure ;
6. coût des profils sobre / normal / riche ;
7. coût de la réduction du mouvement ;
8. impact réseau du contrat ;
9. consommation/charge machine dans un scénario représentatif lorsque le matériel de test est disponible.

Aucun seuil chiffré de production n'est fixé avant ces mesures.
