# PROTO-0.2 — Index de développement

## Point d’entrée humain / Codex

- `CODEX_START_HERE.md` — instruction de lancement de l’agent.
- `CURRENT_TASK.md` — tâche active à exécuter.
- `TONIGHT_RUN.md` — cadrage spécifique du run de 3–5 h.

## Référentiels du prototype

- `00_CHARTER.md` — but et nature de PROTO-0.2.
- `01_RULES_AND_SCOPE.md` — règles actées et hors périmètre.
- `02_UX_SPEC.md` — ergonomie fonctionnelle recherchée.
- `03_TECHNICAL_GUARDRAILS.md` — qualité attendue des briques réutilisables.
- `04_ACCEPTANCE.md` — gates de validation.
- `05_EXECUTION_PLAN.md` — organisation des créneaux autonomes.

## Boucle d’itération

- `TASK_QUEUE.md` — lots suivants possibles.
- `PLAYTEST_FEEDBACK.md` — retours utilisateur à trier.
- `DECISIONS_NEEDED.md` — uniquement les décisions de conception non résolues.
- `IMPLEMENTATION_REPORT.md` — rapport Codex de fin de lot.

## Règle générale

PROTO-0.2 est une expérience de **mini-jeu jouable pour tester ergonomie et règles**. Il n’est ni une démo artistique, ni une version de production, ni le moment d’introduire le contenu futur non nécessaire.

Les parties destinées à survivre (modèle, primitives d’interaction, composants génériques, persistance, présentation des modificateurs) doivent être construites proprement. Le reste peut rester volontairement expérimental tant qu’il est compréhensible et réversible.
